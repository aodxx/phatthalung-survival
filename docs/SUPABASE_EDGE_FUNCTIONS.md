# Supabase Edge Functions — Production Transport Inventory

เอกสารนี้บันทึก boundary ที่ deploy ไปยัง Supabase project `ulawoqswzqfpqyssxggn` ระหว่าง production transport migration ของแอปพัทลุงต้องรอด โดยใช้ TEST data เท่านั้นในการตรวจสอบ

| Function                     | HTTP contract                                                | Authentication boundary                                                                   | Mutation/data boundary                                                                                                   | Current evidence                                                                                             |
| ---------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `public-intake`              | `POST` JSON citizen intake; `OPTIONS` CORS                   | Public endpoint; no citizen login gate; validates payload before calling service-role RPC | Calls `public.submit_public_intake_atomic(jsonb)`; returns `RECEIVED` with Case ID/token or tokenless `ALREADY_RECEIVED` | TEST call returned HTTP 200 `RECEIVED`, duplicate returned HTTP 200 `ALREADY_RECEIVED` without a new token   |
| `public-tracking`            | `POST` JSON `{ caseCode, trackingToken }`                    | Public endpoint; authorization is Case ID + SHA-256 tracking token                        | Reads request, incident/mission lifecycle, and READY-only attachment metadata through service-role client                | Wrong TEST token returned HTTP 404; successful tracking path still requires a real acknowledged TEST fixture |
| `public-attachment-upload`   | `POST` binary body with case/token/client attachment headers | Public endpoint; validates Case ID + token, UUID, MIME, size, and count                   | Writes pending/uploading/READY metadata, uploads to private `attachments` bucket, and records upload audit event         | Deployment completed; live READY/upload/download path remains a required next smoke gate                     |
| `public-attachment-download` | `POST` JSON `{ caseCode, trackingToken, attachmentId }`      | Public endpoint; validates Case ID + token and attachment ownership                       | Returns a five-minute signed URL only for READY metadata in the private bucket                                           | Deployment completed; authorized signed URL path remains a required next smoke gate                          |

All functions use sanitized JSON error responses and restrict browser CORS to the GitHub Pages origin. The Supabase service-role key is read only from the Edge Function environment and is never exposed to the browser. The frontend keeps the Manus/tRPC path as the preview adapter and uses `VITE_RUNTIME_BACKEND=supabase` to select the Supabase Functions adapter.

## Evidence and limitations

The TEST critical path established so far is the atomic intake acknowledgement, duplicate idempotency response, wrong-token tracking denial, and fail-closed cleanup attempt. The deployment is **not yet a full production-readiness claim** because the GitHub Pages build must be run with Supabase runtime configuration and the attachment upload/download READY state still needs a complete acknowledged-Request fixture and cleanup verification.

The deployed function source must be checked into `supabase/functions/` before the migration checkpoint is considered complete. This is a reproducibility requirement and an explicit remaining implementation item, not an assumption that the deployed dashboard version is sufficient.
